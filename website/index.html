Serving the local frontier.

halogen™ is local inference that behaves like a frontier API. Qwen3.8-Flash-Next and a set of small NPU models, served from one AMD Strix Halo machine over the APIs your agents already speak.

Release {{version}}
mkdir -p ~/halogen-models

podman run --rm -p 8731:8731 \
  --device /dev/kfd --device /dev/dri --group-add keep-groups \
  --ipc=host --ulimit memlock=-1:-1 \
  -e HALOGEN_DOWNLOAD=peonist-ai/halogen-qwen3.8-flash-next \
  -v ~/halogen-models:/models \
  ghcr.io/peonist-ai/halogen-flash-server:{{version}}

Set the BIOS carve-out (UMA frame buffer) to its minimum, not Auto: this engine wants host RAM, not dedicated VRAM. The weights, about {{fig:req.weights}}, are fetched on first start. The server answers on port 8731, OpenAI-compatible.

System requirements

RequiredNotes
Machine

An AMD Strix Halo machine: Ryzen AI Max+ 395, 128 GB. One GPU, gfx1151 only; the build rejects other architectures. Built to own its machine: the weights stay resident and the KV pool is reserved up front, which on a 128 GB machine leaves roughly {{fig:req.free}} free.

Operating system

Native Linux only. WSL2 is not a supported host.

Kernel

AMD's two gfx1151 fixes to the KFD driver, with CONFIG_HSA_AMD_SVM built in. AMD's floor is Linux 6.18.4, Ubuntu 24.04 HWE 6.17.0-19.19~24.04.2, or Ubuntu 24.04 OEM 6.14.0-1018, each or later.

BIOS

The UMA frame buffer (dedicated graphics memory) at its smallest explicit value, not Auto.

Containers

Podman with --group-add keep-groups. On Docker, use --group-add video --group-add render instead.

Disk

The first start fetches the weights, about {{fig:req.weights}}.

NPU models (optional)

The NPU driver, XRT with its NPU plugin, the NPU firmware, and the IOMMU on. The GPU's fabric clock held at its top speed, or the server refuses to start and prints the commands for your machine.

Sources: host settings, a machine of its own, NPU host details, Quickstart, limits.
