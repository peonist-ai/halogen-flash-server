Test setup

Published 0.18.0 image at its defaults (prompt cache on unless a row says otherwise, greedy, thinking off), one checkpoint a machine: AMD Ryzen AI Max+ 395, 128 GB, Ubuntu 24.04 with kernel 6.17 and no kernel boot options, about 85 W of sustained package power.

The GPU clock was a median 2,358 MHz during prefill and 2,500 to 2,750 MHz during decode. Decode by kind is one request at a time with the prompt cache off. v2 is the default checkpoint.

The repetitive prompts ("print the word red ten times", count to 300, the alphabet on 25 lines, a sentence 40 times, one word 300 times) are the best case, shown so it can be compared like for like.

The 0.18.15 rows use the published 0.18.15 image at its defaults.

Test setup

Three sessions a checkpoint. Each opens with a system prompt, four tools (read, edit and write a file, run the tests), a task, and file reads already answered, 27,000 to 34,000 tokens in all.

Each later turn sends the conversation back with the model's own tool call and a tool result of 800 to 3,000 tokens appended, until the prompt passes 96,000 tokens, answers capped at 512 tokens.

Times are the client's, over HTTP, from the request to the last byte. The two checkpoints write different answers to the same turn, so their turn times differ by the answers' length as much as by speed.

Test setup

0.18.11 against 0.18.10 with HALOGEN_SPEC_GROUP=0 (0.18.10's way of decoding three or four requests) against its default. Figures are that setting / the default, total tok/s.

Each request its own short prompt, 384 tokens, greedy code, prompt cache off, the mean of two server starts on each of two further machines of the same kind for each checkpoint.

Sampled prose (temperature 0.7) gains 13 to 14% at three requests and 9 to 10% at four; one, two, six and eight requests decode as before.

Test setup

One Strix Halo. Figures are as the NPU page states them, with the approximation marks it uses (~, about). Host: NPU driver, XRT, firmware, IOMMU on, the GPU's fabric clock held at its top speed.

Decisions: one question a request, served alone, the request's wall (HTTP included), with one of the two loaded. Loaded together they share the NPU's memory, and d3-nano's questions about pictures take 15 to 25% longer. The pictures are scaled to between 256 x 256 and 768 x 768 worth of pixels.

The image model holds about 8 GB of the host's memory while it is loaded. One image request runs at a time on the NPU, queued with the other NPU models' work.

Speech: the talker runs on the NPU and the audio is decoded on the CPU. The NPU speaks one request at a time.

The docs publish no timing figures for decider-0.8b alone, qwen3.5-2b, or speech to text, so none appear here.
